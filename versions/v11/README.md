## 1. 두 갈래 (A)

v8~v10 은 "백엔드를 글자 그대로 옮긴다" 가 규칙이었습니다. v11 은 다릅니다 —
**백엔드가 안 한 일도 해보고, 더 나은지 숫자로 답합니다.** 다만 섞으면 안 됩니다.

```
MIRROR    백엔드 develop 그대로        ← 기준선
PROPOSAL  우리가 더 낫다고 보는 것      ← 비교 대상
```

비교는 **arm 끼리만** 합니다.

| | MIRROR | PROPOSAL |
| --- | --- | --- |
| `edit()` 의 `형태:` | 없음 (백엔드가 뺌) | **있음** |
| 라우터 스키마 | `{op, target}` | **`{ops:[{op,target,content}]}`** |

**shape 를 왜 다시 보나** — 백엔드가 뺀 이유는 *"모델이 구조를 갈아엎어서
디자인이 망가진다"* 인데, 그건 **추론이지 측정이 아닙니다.** v10 은 shape 를
주고도 D군 9/9 였습니다. 정말 방해였는지 여기서 답합니다.

> 앞서 나가는 것 자체는 문제가 아니고, 라벨만 정확하면 됩니다.

### R — 라우터 새 스키마 (E) ★ 신규

지금 스키마엔 두 가지가 동시에 빠져 있고, **같은 구멍**입니다 — op 하나 · target 하나.

```json
MIRROR    {"op":"EDIT","target":"benefits"}
PROPOSAL  {"ops":[{"op":"EDIT","target":"hero","content":"가을 대축제"},
                  {"op":"EDIT","target":"benefits","content":null}]}
```

★ **결정 ③("라우터는 분류만, 거부는 서버")을 깨지 않습니다.**
라우터에게 "내용이 충분한지 판단해라" 를 시키면 판단이 라우터로 넘어갑니다.
그래서 **추출만** 시킵니다 — 있으면 쓰고 없으면 `null`.
`null` 을 보고 되물을지 정하는 건 **서버**입니다.

| | 요청 | 보는 것 |
| --- | --- | --- |
| R1 | 혜택에 '데이터 10GB 증정' 추가 | content 를 정확히 뽑는가 |
| **R2** | **"혜택 하나 더 추가해줘"** | **`content: null` 을 내는가** ← 되묻기의 전제 |
| R3 | 제목 바꾸고 혜택도 추가 | 복합을 ops 둘로 쪼개는가 |
| R4 | 버튼 문구 바꾸고 참여방법도 | 한쪽만 내용이 있을 때 |
| R5 | 유의사항 문구 바꿔줘 | `notices` 로 **분류만** 하는가 (거부는 서버) |

**R2 가 핵심입니다.** 모델이 `null` 을 못 내고 지어내서 채우면
**되묻기는 이 설계로 불가능**하고 폼 방식으로 가야 합니다.

### ⚠ 되묻기 **자체는 안 쟀습니다** — 전제 하나만 쟀습니다

R군이 답한 건 *"라우터가 `content: null` 을 낼 수 있는가"* 하나입니다(14/14 ✅).
**되묻기 흐름은 아무것도 안 쟀습니다.** 남은 셋:

**① 어떤 `null` 이 "되물을 null" 인가 — 구분이 안 됩니다**

v11 은 `null` 을 두 자리에서 기대했는데 **의미가 정반대**입니다.

```
R2  "혜택 하나 더 추가해줘"          → content: null   ← 내용이 빠졌다. 되물어야 함
R4  "참여 방법도 더 친절하게 다듬어줘" → content: null   ← 방향만 말했다. 되물으면 안 됨
```

**출력이 똑같아서 서버가 둘을 못 가릅니다.** 이 프롬프트가
*"바꿀 방향만 말했으면 content 는 null 이다"* 라고 적어서 **일부러 합쳐놨는데**,
되묻기를 붙이려면 **갈라야 합니다.**

가를 방법 후보 — 어느 쪽도 **미측정**입니다:
- 라우터가 `needs_input: true` 를 따로 낸다 → 판단이 라우터로 넘어가 **결정 ③ 위반**
- 서버가 `op`·블록 성격으로 정한다 → `benefits` 는 `minItems>0 && MIXED`(폼 값)라
  "항목 추가" 면 내용이 필요하고, `steps` 문구 다듬기는 아니다.
  `Block.itemsAreFormValues()` 가 백엔드 주석에 **이름만 있고 구현이 없습니다.**

**② 2차 호출을 어떻게 합치나** — 사용자가 답한 뒤
**이전 요청 + 답변**을 한 번에 넘길지, 합쳐서 새 문장으로 만들지 미측정입니다.

**③ 서버가 되묻는 것 자체** — LLM 과 무관한 서버 로직이라 벤치마크 대상이
아닙니다. 구현하면 됩니다.

> 즉 **"되묻기가 가능하다" 까지만 확인됐고, "어떻게 할지" 는 설계가 먼저입니다.**

> R3·R4 에서 MIRROR 는 `schema_cannot_express` 로 실패합니다.
> **모델 탓이 아니라 스키마 탓**이고, 그게 측정 결과입니다.
> 코드 이름을 따로 둬서 모델 실패와 섞이지 않게 했습니다.

| ① | "추가해줘" → `ADD` (`benefits` 는 `required=true` 인데) | 6 |
| ② | "부드럽게·친절하게" → `STYLE` (겉모양이 아닌데) | 2 |

#### 먼저, 흔한 오해 하나

*"라우터가 문서를 안 받아서 `benefits` 가 있는지 모른다"* — **아닙니다.**

```
benefits.required     = true    → 모든 유효한 문서에 항상 존재
benefits.canCreate()  = false   → ADD 가 정의상 불가능
```

`Block.canCreate()` 가 **이미** 이 판단을 합니다. 5개 중 ADD 가 말이 되는 건
**`steps` 하나뿐**입니다(유일한 `required=false`). 문서를 볼 필요가 없습니다.

> 문서 상태가 정말 필요한 건 `steps` 뿐이고(선택 블록), 그것도 서버가
> `blockOf(doc, STEPS)` 로 보면 됩니다. **라우터에 문서를 줄 이유는 없습니다.**

#### 그래서 프롬프트로 고쳐봤습니다 — **효과 0**

`router()` 는 다섯 블록을 평평하게 나열합니다. `generate()` 는
`llmBlocks()`·`serverBlocks()` 로 나눠 *"만들면 안 되는 영역"* 을 명시하는데
**`router()` 만 그걸 안 합니다.** 그래서 PROPOSAL 에 레지스트리에서 뽑은 줄을 넣고
같은 케이스를 다시 돌렸습니다(20호출 · 2원).

```
- "ADD"     없는 영역을 새로 넣는다  (steps 만 가능)
- "DELETE"  영역을 통째로 지운다  (steps 만 가능)
- 이미 있는 영역의 **내용**을 더하거나 빼는 것은 EDIT 이다.
```

```json
결과:  {"ops":[{"op":"ADD","target":"benefits","content":null}]}
                      ↑ "steps 만 가능" 이 바로 위에 적혀 있는데도 benefits

op 4/12 → 4/12      ADD 오류 6건 → 6건      변화 없음
```

**금지를 명시해도, 가능한 블록을 열거해도, EDIT 이라고 직접 알려줘도 안 됩니다.**
2회씩 일관되게 같은 답이라 변덕도 아닙니다. 동사 "추가" 와 op 이름 `ADD` 의
어휘 대응이 다른 지시보다 강합니다 — ②(`STYLE`)도 같은 패턴입니다.

#### 결론 — 서버가 해야 한다

```java
if (op.equals("ADD") && !block.canCreate())  op = "EDIT";
```

`canCreate()` 가 이미 있으니 **한 줄**이고, 결정 ③("라우터는 분류만, 거부는
서버")에도 맞습니다. 그리고 이건 *"그게 더 깔끔해서"* 가 아니라
**"프롬프트로 두 번 해봤고 둘 다 실패해서"** 입니다.

> 부차적으로 `ADD` → `CREATE_SECTION` 처럼 **op 이름을 "추가" 와 안 겹치게**
> 바꾸는 선택지도 있습니다. 다만 백엔드 계약 변경이라 서버 한 줄보다 비쌉니다.
> **측정 전이라 권하지 않습니다.**

★ PROPOSAL 의 그 세 줄은 **효과 0 이지만 남겨뒀습니다.** 해롭지 않고,
나중에 같은 생각을 하는 사람이 2원을 아낍니다.

★ **v8 의 진단도 틀렸습니다.** 당시 qwen 두 모델이 R1 에서 ADD 로 틀린 걸
"qwen 계열 공통 약점" 으로 적었는데, 문구가 "추가해줘" 로 바뀌자 **gemma 도
똑같이 틀립니다.** 계열 문제가 아니었습니다.
