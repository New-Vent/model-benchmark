# v9 — 정화가 생성·수정에서 갈린 조건

**v8 과 케이스는 같고 파이프라인이 다릅니다.** 그래서 v8 이 못 재던 축
하나(슬롯 보존)가 측정 가능해졌습니다. 모델 순위는 v8 과 같습니다.

기준: backend `develop` @ `9fd0c64`

---

## 1. v8 과 무엇이 다른가

| | v8 | **v9** |
| --- | --- | --- |
| 정화 | 단일 `sanitize` | **`sanitize_generated` / `sanitize_edited`** |
| `data-slot` | 두 경로 모두 **삭제** | 생성 삭제 · **수정 보존** |
| `href="#"` | **삭제** | **보존** |
| 수정 프롬프트 | 슬롯 규칙 없음 | "건드리면 안 되는 것" 3줄 |
| 생성 검증 | 슬롯 검사 있음 | 없음 (정화가 지우므로 불필요) |
| 재시도 | 3회 | **4회** |
| 돌릴 수 있는 케이스 | G2·E4·R8·C2 | **+ E1·E2·C1** |

케이스 정의 자체는 v8 과 동일합니다. 달라진 건 **슬롯이 든 케이스를 돌릴 수
있게 됐다**는 것입니다.

### 핵심 — 정화가 슬롯에서 정반대로 동작한다

```
생성  sanitize_generated   data-slot 을 지운다   빈 문서라 있을 이유가 없다
수정  sanitize_edited      data-slot 을 남긴다   원본에 있던 걸 보존해야 한다
```

한쪽 규칙을 양쪽에 쓰면 *"제목 한 번 고쳤을 뿐인데 그 이벤트는 기간을 영원히
못 채우는"* 사고가 납니다 — `merge()` 가 블록을 통째로 갈아끼우기 때문입니다.

`data-slot` 은 서버가 폼 값을 써 넣는 자리표입니다(`Slot.PERIOD`,
`Slot.CTA_LINK`). 수정 중에 지워지면 그 자리에 값을 채울 방법이 영영 없어집니다.

**대신 새 위험이 생깁니다** — 정화가 슬롯을 통과시키므로 모델이 **없던 슬롯을
지어낼** 수 있습니다. 진짜와 가짜를 정화 단계에서는 구별할 수 없어서,
`validate_edited` 가 **원본과 대조**해서 잡습니다.

| | |
| --- | --- |
| 원본에 있었는데 없어짐 | `slot_lost_*` |
| 원본에 없었는데 생김 | `slot_invented_*` |

"지우기"를 포기한 대신 "대조하기"로 막는 구조라, **둘은 한 쌍입니다.**

### 파이프라인 차이 확인 — 호출 0원

`LLM_PROVIDER=mock`(= 아무것도 안 바꾸는 완벽한 모델)으로 C1 을 3턴 돌린 결과:

| | v8 | **v9** |
| --- | --- | --- |
| FINAL_DOC 슬롯 | 전부 사라짐 | **`['period', 'cta-link']`** |
| FINAL_DOC href | 전부 사라짐 | **`['#']`** |
| 정화 손상 | 8건 | **0건** |

모델은 한 글자도 안 틀렸는데 v8 에서는 문서가 망가졌습니다.

## 3. 확인된 것

| 질문 | 답 |
| --- | --- |
| 모델이 슬롯을 **지우는가** (`slot_lost`) | **아니오** — 0건 |
| 모델이 슬롯을 **지어내는가** (`slot_invented`) | **아니오** — 0건 |
| `class` · `href` 보존 | **완벽** — 0건 |

```html
E1 요청: 버튼 문구를 '지금 응모하기' 로 바꿔줘
결과:    <a href="#" class="btn" data-slot="cta-link">지금 응모하기</a>
                ↑유지     ↑유지        ↑유지          ↑변경
```

C1 3턴 누적 후에도 슬롯 둘과 `href="#"` 가 전부 살아 있습니다.
수정 프롬프트의 "건드리면 안 되는 것" 3줄이 잘 먹은 것으로 보입니다.

## 4. 읽을 때 주의

**① `slot_invented` 0건은 "안 난다"가 아닙니다.** 모델당 15호출이고 슬롯이 든
baseline 이 2종(cta·hero)뿐입니다. 서버가 엉뚱한 자리에 폼 값을 쓰게 만드는
**드물지만 치명적인** 실패라, 표본으로 부재를 증명할 수 없습니다. 검사기가
작동하는 것은 별도로 확인했습니다(가짜 입력으로 `slot_invented_period` 발화).
**검사기 유지가 결론입니다.**

**② v8 과 "최종 통과율"을 직접 빼지 마세요.** 재시도 횟수가 다릅니다(3 vs 4).
**1차 통과율끼리** 비교하세요 — Bedrock 에서는 그게 곧 비용이기도 합니다.

**③ v9 는 모델 순위를 가르는 버전이 아닙니다.** v8 에서 갈린 축은 라우터였고
(qwen 16/24 · oss120 22/24), 라우터는 재시도가 없어 v9 변경과 무관합니다.

## 5. 실행

```bash
export BEDROCK_REGION=us-east-1

python versions/v9/run_v9.py --self-check          # 호출 없이 코드 검증만
LLM_PROVIDER=mock python versions/v9/run_v9.py     # 0원, 배선 확인

BEDROCK_MODEL=gemma LLM_PROVIDER=bedrock RUNNER=OO \
  python versions/v9/run_v9.py --repeats 3         # 전체, 약 7원

python versions/v9/run_v9.py --cases E1,E2,C1      # 슬롯 케이스만
python versions/v9/run_v9.py --skip-slot-cases     # v8 조건 재현용
```

`mock` 은 "완벽한 모델"이라 **남는 실패가 전부 파이프라인 탓**입니다.
모델을 바꿔도 안 고쳐지는 문제를 0원에 먼저 잡으라고 둔 장치입니다.

군 구성과 채점 방식은 [v8 README](../v8/README.md) §2 와 같습니다.

### 파일

`registry_v9.py`(Block+Slot) · `prompts_v9.py`(PromptBuilder) ·
`checks_v9.py`(BlockValidator) · `provider.py`(LlmClient+Bedrock) ·
`cases_v9.py` · `run_v9.py` — 앞 셋은 백엔드 미러입니다.

> ⚠ **백엔드가 프롬프트·레지스트리·정화를 고치면 여기도 같이 고쳐야 합니다.**
> 자동 감지 방법이 없습니다. `self_check()` 는 Python 쪽 일관성만 봅니다.
