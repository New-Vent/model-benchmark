## 2. 알아낸 것 셋

### ① qwen 이 `data-slot` 을 스스로 지어낸다

```html
<span data-slot="benefit-1-name">   ← 원본엔 슬롯이 하나도 없던 블록
```

**모델이 서버의 쓰기 지점을 스스로 만들었습니다.** `sanitizeEdited` 가
`data-slot` 을 통과시키니 정화로는 못 막고, `checkPreserved` 의 대조만이 잡습니다.
v9 가 *"실제로 발생하는지는 아무도 모른다"* 고 남긴 축의 답입니다 — **모델에 따라 납니다.**

렌더해보니 더 심합니다. 복주머니 카드 3장(福 이미지·확률 배지·버튼)이
**맨 텍스트 2줄**로 전락했습니다.

### ② 백엔드의 **좁은** class 검사가 맞았다

```
gemma · haiku   class_changed  0건        ← 오탐 0
qwen            class_changed_root  7/9   ← 실제 파괴를 정확히 집음
```

이름표(root·slot·id)만 보는데, qwen 이 root 에서 `ev-block` 을 떨어뜨리는 걸
잡았습니다. `Slots.classMap()` 주석이 *"ev-block 이 제일 위험하다 — 태그도
슬롯도 id 도 멀쩡한데 디자인만 달라진다"* 고 적어둔 바로 그 사고입니다.

> v10 이 같이 쓴 **집합 기반 `class_lost`** 는 백엔드가 **의식적으로 거부한**
> 정책입니다("이 문구 강조해줘" 로 `span.highlight` 가 느는 것까지 묶임).
> §4 에서 점수 밖으로 뺐습니다.

### ③ 출력 캡 — `benefits` 만 위험하다

haiku 8건 · oss120 3건 `truncated`, gemma 0건.
benefits 는 **원본만 811토큰**(캡 1536 의 53%)이고, 하필 "항목 하나 더 추가" 를
시키는 블록입니다. **Bedrock 에서 재시도는 과금**이라 1차 통과율이 실질 비용입니다.

## 3. ⚠ 채점기를 네 번 고친 뒤의 숫자다

처음엔 gemma 12/27 이었습니다. **전부 검사·케이스 문제였고 모델은 안 틀렸습니다.**

| 고친 것 | 문제 |
| --- | --- |
| `class_lost` | 제목 교체 시 안쪽 `<span class="highlight">` 손실 → 인라인 제외 |
| `hook_lost` | **삭제를 시킨** 항목의 훅을 잡음 → 삭제분 허용 |
| `invented_content` | 항목 **설명 문구**를 환각으로 오인 → **수치 보존**으로 교체 |
| `want_text` (D1) | "데이터 10GB 증정" 정확 일치 → **수치만** |

★ **오탐은 되먹임을 타고 모델을 망가뜨립니다.**

```
D2 "마지막 항목 하나를 삭제해줘"
   시도1   카드 3→2, 훅 3→2   ← 정확히 시킨 대로
           (검사: "data-demo-msg 를 지웠습니다")
   시도2~4 훅 0개              ← 모순된 지시에 남은 것마저 떼어냄
```

**재시도 데이터는 못 쓰고 1차만 유효합니다.** v4 의 "틀린 지시가 모델을
망가뜨린 것" 과 같습니다. 원인은 `self_check` 에 "원본 무변경" 만 넣고
**"시킨 대로 한 출력이 통과하는가"** 를 안 넣은 탓입니다(v11 에서 넣었습니다).

## 5. ★ 렌더 — 블록 간 내용 참조가 조용히 어긋난다

`render_v10.py` · 0원. **렌더링 없이는 알 수 없던 것이고, v10 최대 발견입니다.**

```
template_3   benefits  카드 3장
             steps     "감사 쿠폰팩 3종 일괄 다운로드"   ← 개수를 문장에 박아둠
             cta       "감사 쿠폰팩 3종 한번에 받기"
```

| 모델 | 요청 | 결과 카드 | cta 문구 | |
| --- | --- | :-: | :-: | --- |
| gemma · haiku | 혜택 1개 **추가** | 4개 | "3종" | ✗ |
| gemma · haiku | 혜택 1개 **삭제** | 2개 | "3종" | ✗ |

**네 건 전부 검사를 통과했습니다.** 그리고 **모델 탓이 아닙니다** —
모델은 `benefits` 만 받아서 다른 블록을 모르고, 검증기도 `merge()` 도 그 블록
하나만 봅니다. **부분 재생성 설계 자체의 구멍**이라 검증기로는 못 막습니다.

실서비스에 나면 사용자가 **"쿠폰팩 3종" 버튼을 누르는데 혜택은 4개**입니다.

고치는 안 셋 — **①이 가장 쌉니다**(슬롯 메커니즘이 이미 있음):

| | 방법 | 비용 |
| --- | --- | --- |
| **①** | `data-slot="benefit-count"` 를 두고 **서버가 채운다** | 템플릿 수정 |
| ② | 개수 바뀌면 참조 블록도 같이 재생성 | 호출 2배 |
| ③ | "steps·cta 도 확인하세요" 경고 | 0원, UX 부담 |

### 검사와 눈이 일치했다 (그리고 한 번은 절반만)

- **gemma H1** ✓ — 4번째 카드가 나머지 셋과 **같은 시각 언어**(아이콘 배지·태그·버튼)
- **qwen D1** ✗ — 카드 전멸. 채점기가 과하지도 모자라지도 않았음
- **P2** — `class_lost_highlight` 로 실패 처리하고 4번 재시도시킨 건 **과했지만**,
  강조 색 2줄 제목이 흰색 1줄이 된 것도 사실입니다. **숫자로는 통과, 눈으로는 하나 빠짐**
