**실행 완료.** 4모델 · 886원 — 결과는 §7.

## 무엇을 봤나

v8·v9 가 만점만 내서 변별이 안 됐습니다. **baseline 이 너무 단순했기 때문**입니다.

| | v8·v9 | **v10** |
| --- | --- | --- |
| baseline | `Block.shape` 최소 마크업 | **실제 템플릿 5종** |
| class | **1개** (`btn`) | **451건** |
| 블록 크기 | ~150자 | **최대 2,229자** |
| benefits | `<ul><li>` | **`<div class="benefit-card">`** |
| cta | `<a href="#">` | **`<button>`** |

실제 템플릿으로 바꾸고 세 가지를 봤습니다.

| | 질문 | 답 |
| --- | --- | --- |
| **D** | `must` 는 통과하는데 **디자인이 깨지는가** | qwen 만 1/3 |
| **P** | class·slot·id·훅이 **남는가** | 4모델 전부 통과 |
| **H** | **준 것만** 쓰는가 (수치 보존) | qwen 만 2/3 |

**1순위는 v8·v9 와 같은 `google.gemma-3-27b-it`** (27/27, haiku 와 동점에 비용 1/11).

**qwen3-coder 만 무너집니다** — `data-slot` 을 **스스로 지어냈고**(`benefit-1-name` 등)
블록을 통째로 다시 썼습니다. v9 가 "아직 아무도 모른다"고 남긴 축의 답입니다.

## 1. 세 군

| 군 | 재는 것 | 케이스 |
| --- | --- | :-: |
| **D** Design | **must 는 통과하는데 디자인이 깨지는가** | 3 |
| **P** Preserve | 실제 환경에서 class·slot·id·훅이 남는가 | 3 |
| **H** Halluc | ④ — 준 것만 쓰는가 | 3 |

생성(G)·라우터(R)·체인(C)은 넣지 않았습니다. 템플릿은 **수정 대상**이고,
라우터는 문서와 무관해서 v9 결과가 그대로 유효합니다.

### ★ D — 아무 검사도 못 잡던 구멍

```
shape   "<ul> 안에 <li> 로 항목을 나열한다"      ← 모델에게 시키는 말
must    "ul li, .benefit-card"                   ← 둘 다 받는다
템플릿   <div class="benefit-card sp-prize-main"> ← 실제 마크업
```

**모델이 shape 대로 하면 디자인이 깨집니다.** "혜택 하나 추가해줘" 를 받고
`<ul><li>` 로 바꿔버리면:

| 검사 | 결과 |
| --- | --- |
| `must="ul li, .benefit-card"` | ✅ 통과 (`ul li` 3개) |
| 백엔드 `classMap` 검사 | ✅ 통과 (`.benefit-card` 엔 id·slot 이 없어 **이름표가 없음**) |
| **실제 화면** | ❌ **CSS 가 안 먹어 무너짐** |

v10 이 이걸 처음 잽니다. 실측으로 확인했습니다.

```
① card→li 변환   must 통과? True   항목수(.benefit-card): 0
   class_lost: ['class_lost_benefit-card', 'class_lost_benefit-tag']
```

### 두 가지 class 검사를 같이 씁니다

| | 백엔드 `classMap` | v10 집합 방식 |
| --- | --- | --- |
| 대상 | root · `data-slot` · `id` 요소 | 문서 전체 클래스 |
| 감지 | class **변경** | class **유실** |
| `.benefit-card` → `<li>` | ❌ 못 잡음 | ✅ 잡음 |
| 오탐 | 0 | 0 (실측) |

**보완 관계**라 둘 다 넣었습니다.

### 항목 수는 `must` 가 아니라 템플릿 선택자로 셉니다

`must` 로 세면 `<li>` 로 바뀌어도 개수가 맞아 통과합니다. 그게 잡으려는
구멍이라, 공통 클래스(`.benefit-card`)로만 셉니다.

### v9 가 예고한 위험이 실제로 났다 — `slot_invented`

```
원본 benefits 슬롯 : 없음
qwen 출력 슬롯     : benefit-1-name · benefit-1-desc · benefit-2-name · benefit-2-desc
```

```html
<span data-slot="benefit-1-name">
```

**모델이 서버의 쓰기 지점을 스스로 만들었습니다.** `sanitizeEdited` 가
`data-slot` 을 통과시키니 정화로는 못 막고, `checkPreserved` 의 대조만이 잡습니다.
v9 README 에 "실제로 발생하는지는 아직 아무도 모른다"고 적어둔 축인데 —
**모델에 따라 납니다.** 백엔드의 그 검사가 실제로 필요했던 방어였습니다.

H3 에서는 `.step-card` 를 `<li data-slot="step1">` 으로 감싸며 블록을 통째로
다시 썼습니다(`class_lost` 7종 + `slot_invented` 10종). shape 가 "`<ol>` 안에
`<li>`" 라고 시키니 템플릿 구조 위에 자기 방식을 덧씌운 것입니다.

### ⚠ 이 결과는 채점기를 **네 번 고친 뒤**의 것이다

처음엔 gemma 12/27 · haiku 13/27 이었습니다. **전부 검사·케이스 문제였고
모델은 안 틀렸습니다.**

| 고친 것 | 문제 |
| --- | --- |
| `class_lost` | 제목 교체 시 안쪽 `<span class="highlight">` 손실 → 인라인 제외 |
| `hook_lost` | **삭제를 시킨** 항목의 훅을 잡음 → 삭제분 허용 |
| `invented_content` | 항목 **설명 문구**를 환각으로 오인 → **수치 보존**으로 교체 |
| `want_text` (D1) | "데이터 10GB 증정" 정확 일치 → **수치만** |

그리고 **오탐은 되먹임을 타고 모델을 망가뜨립니다.** D2 는 시도1 이 통과였는데,
버그난 검사가 재시도를 부르자 시도2·3 에서 훅이 전멸했습니다(v4 의
"틀린 지시가 모델을 망가뜨린 것"). **재시도 데이터는 못 쓰고 1차만 유효합니다.**

v4 교훈("채점기를 먼저 채점하라")을 적어두고도 같은 실수를 했습니다 —
`self_check` 에 원본 무변경만 넣고 **"시킨 대로 한 출력이 통과하는가"** 를
안 넣은 탓입니다. 지금은 넣었습니다.
