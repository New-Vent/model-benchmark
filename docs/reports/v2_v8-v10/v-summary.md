### v9 가 예고한 위험이 실제로 났다 — `slot_invented`

```
원본 benefits 슬롯 : 없음
qwen 출력 슬롯     : benefit-1-name · benefit-1-desc · benefit-2-name · benefit-2-desc
```

**모델이 서버의 쓰기 지점을 스스로 만들었다.** `sanitizeEdited` 가 `data-slot`
을 통과시키니 정화로는 못 막고, `checkPreserved` 의 대조만이 잡는다. v9 README
가 "실제로 발생하는지는 아직 아무도 모른다"고 남긴 축인데 — **모델에 따라
난다.** H3 에서는 `.step-card` 를 `<li data-slot="step1">` 으로 감싸며 블록을
통째로 다시 썼다(`class_lost` 7종 + `slot_invented` 10종).

### ⚠ 이 결과는 채점기를 네 번 고친 뒤의 것이다

처음엔 gemma 12/27 · haiku 13/27 이었다. **전부 검사·케이스 문제였고 모델은
안 틀렸다.**

| 고친 것 | 문제 |
| --- | --- |
| `class_lost` | 제목 교체 시 안쪽 `<span class="highlight">` 손실 → 인라인 제외 |
| `hook_lost` | 삭제를 시킨 항목의 훅을 잡음 → 삭제분 허용 |
| `invented_content` | 항목 설명 문구를 환각으로 오인 → 수치 보존으로 교체 |
| `want_text` (D1) | "데이터 10GB 증정" 정확 일치 → 수치만 |

**오탐은 되먹임을 타고 모델을 망가뜨린다.** D2 는 시도1 이 통과였는데, 버그난
검사가 재시도를 부르자 시도2·3 에서 훅이 전멸했다(v4 의 "틀린 지시가 모델을
망가뜨린 것"과 같은 패턴). **재시도 데이터는 못 쓰고 1차만 유효하다.**
